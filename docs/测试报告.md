## 交互验证范围

自动流程从食品详情页增加商品，进入购物车结算，创建本地订单，经过成功页进入地图，确认收货并提交评价，最终回到历史订单。断言包含购物车内容、创建订单、清空已结算购物车及配送完成状态。

持久化测试使用独立存储模拟，验证重新创建状态对象后可以恢复已保存的资料、地址、收藏、订单和通知偏好。金额测试检查数量及折扣后总价，避免纯界面演示时的固定金额。

截图使用预置的演示状态，购物车和收藏非空，历史与进行中订单均有样例。优惠码购物车画面使用三种商品，以同时呈现优惠输入区。图库中的空验证码/PIN 输入框符合尚未输入时的状态，实际键盘只在点击输入框后出现。

## 已知环境限制

本机 Flutter 3.47.7 的 Windows 无界面 UI 测试进程出现原生访问异常 `0xc0000005`。因此界面测试改在 Android 模拟器执行，同一套 49 项页面与流程测试已通过。纯业务状态测试可在本机正常执行。

iOS 平台源码已生成，但当前为 Windows 环境，没有进行 Xcode 构建或 iPhone 测试。Web 平台源码保留，尚未将浏览器运行结果列为通过项。

该验证针对本地 UI 演示；短信、邮件、真实支付、远程聊天、实时地图和后端接口不在当前实现中。详见项目说明的外部服务边界。
